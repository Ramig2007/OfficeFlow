## 4. Минимальный демонстрационный маршрут

1. Показать README и зелёный GitHub Actions на коммите `a1e5e32`; показать наличие Docker-образа в GHCR.
2. Открыть локальный OfficeFlow: вход сотрудника, комнаты и недельное расписание.
3. Создать бронь на свободный интервал, показать её в истории и запрет повторного пересекающегося бронирования.
4. Продемонстрировать VIP: заявка `pending`, вход менеджера, одобрение, обновление статуса.
5. Показать запрет доступа сотрудника к менеджерским функциям и CSV-экспорт для менеджера.
6. Открыть Grafana/Prometheus; показать 3 `UP` источника и состояние правил; объяснить `null-receiver`.
7. Показать документы: E2E 9/9, k6 200 RPS, backup/restore с временной базой, пользовательская приёмка 8/8.
8. Открыто перечислить ограничения: нет доказанного длительного SLA и высоконагруженных записей; нет развёртывания в публичном облаке.

## 5. Проверки безопасности перед демонстрацией

- Не добавлять `.env`, папку `backups/`, локальный `compose.override.yaml` в Git. Четыре вспомогательных неотслеживаемых файла можно оставить локально.
- Не выполнять `docker compose down -v` — это может удалить volumes с данными.
- Не проводить нагрузочные испытания записи, миграции или fault injection на основной базе.
- Проверьте `ALLOWED_HOSTS`: локальная настройка должна включать `localhost`, `127.0.0.1`, `app`, `proxy` **без дополнительного `ALLOWED_HOSTS=` внутри значения**.
- Приватная публикация GHCR сама по себе не даёт преподавателю доступ к образу.
