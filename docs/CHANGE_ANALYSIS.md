# Impact analysis: VIP-подтверждение и CSV

## Исходная функциональность

Обычная комната бронируется напрямую со статусом `confirmed`. При создании и изменении проверяются часовое начало и окончание, 1–4 часа и отсутствие конфликтов. Данные хранятся в PostgreSQL, доступ ограничен ролью.

## Изменение A — VIP-ожидание

**Новое правило:** VIP получает `pending`, блокирует временной слот и не становится `confirmed` без явного действия администратора. Изменение переговорной на VIP повторно требует согласования.

| Затронутый слой | Влияние | Риск | Регрессия |
|---|---|---|---|
| Room | флаг `is_vip` | изменение флага после выданных броней | тест смены VIP при будущих записях |
| Booking | новые статусы pending/rejected | слоты могут быть ошибочно свободны | overlap active statuses |
| Services | approve/reject, блокировки | гонка одобрений/отмен | state transition tests |
| API | admin actions, нельзя передать status | escalation via API | mass-assignment + 403 |
| UI | статусы и список заявок | непонятность пользователям | E2E заявки |
| Metrics | доля ожидающих заявок | задержки согласования | ручной замер в пилоте |
| Docs | OpenAPI, роли, инструкции | инструкции могут устареть | ревью документации |

**Решение:** активными считаются обе записи `pending` и `confirmed`. На уровне PG действует exclusion constraint. Аудит фиксирует actor/reviewer. Только `User.can_manage` имеет право рассматривать заявки.

## Изменение B — CSV

**Новая функция:** администратор получает выгрузку с фильтрами по начальной дате, конечной дате и переговорной. Реализация `queries.py` разделяет отбор и форматирование, обслуживает HTML и REST.

Риски: прямой доступ обычного пользователя, утечка чужих бронирований, CSV injection, неверная интерпретация временной зоны, некорректные фильтры. Меры: 403 на endpoint для не-админа, защитное апострофирование ячеек, UTF-8 BOM и `;` delimiter для Excel, ISO timestamp с offset. Включить в тесты пустой результат, недопустимый room ID, даты по краям, злонамеренный заголовок `=...`.

## Обязательная регрессия

1. Две обычные встречи на соседние часы принимаются.
2. Две пересекающиеся встречи в одной комнате возвращают 409.
3. VIP заявка создаётся pending; попытка `status=confirmed` игнорируется.
4. Pending блокирует время до отказа/отмены.
5. Чужую заявку нельзя ни отменить, ни прочитать через ID.
6. При одобрении указываются reviewer и reviewed_at.
7. Отказ без причины запрещён.
8. CSV доступен только администратору; фильтры корректны.
9. После изменений все тесты проходят на PostgreSQL, а пользовательская навигация/ошибки понятны.

Фактический протокол тестирования заполняется в `PILOT.md` после запуска.
