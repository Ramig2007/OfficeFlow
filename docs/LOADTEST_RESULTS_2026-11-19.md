# OfficeFlow — протокол базового нагрузочного теста (19.11.2026)

Источник данных: фактический вывод локального Grafana k6, предоставленный при ручной проверке проекта. Среда: Docker Compose на компьютере разработчика, endpoint `/health/live/` через Nginx (`http://proxy`). Каждый прогон: 30 секунд. Время p95 — по `http_req_duration` k6.

| Прогон | План | Фактическая интенсивность | HTTP-запросов | HTTP 200 | Ошибки | p95 | Статус |
|---|---:|---:|---:|---:|---:|---:|---|
| Baseline A | 100 RPS | 99,99064 RPS | 3000 | 3000 | 0% | 1,40 мс | Пройден |
| Baseline B | 200 RPS | 199,945545 RPS | 6001 | 6001 | 0% | 1,49 мс | Пройден |

Первый ошибочный прогон 100 RPS (3001 запросов, 0 HTTP 200, p95 1040 мс) признан конфигурационным: внутреннее имя `proxy` не входило в `ALLOWED_HOSTS` Django. После исправления и повторной проверки HTTP 200 повторные прогоны прошли.

**Ограничения выводов:** `/health/live/` не осуществляет запросы к PostgreSQL и не проверяет бизнес-логику бронирований. Результаты характеризуют только этот endpoint на локальном стенде за 30 секунд. Они не подтверждают 99,9% доступности за длительный период и не доказывают p95 для рабочих запросов. Требуются отдельные смешанные, конкурентные и долговременные тесты, а также анализ ресурсов и поведения при деградации БД.
