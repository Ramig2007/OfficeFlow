# OfficeFlow — реестр дефектов и исправлений

**Дата актуализации:** 19 ноября 2026 г.  
**Статус пользовательской проверки:** 8/8 сценариев пройдены; новых дефектов в этом прогоне не заявлено.

## Ранее обнаруженные и устранённые проблемы

| ID | Описание | Область | Исправление / проверка | Статус |
|---|---|---|---|---|
| OF-001 | Ошибка `Bad Request (400)` при открытии `localhost:8080`: значение `ALLOWED_HOSTS` содержало лишний префикс `ALLOWED_HOSTS=` | Локальная конфигурация | Исправлена строка в локальном `.env`; после изменения сайт открылся, 8/8 пользовательских сценариев прошли | Устранено локально |
| OF-002 | GitHub Actions: 15 тестов падали из-за отсутствующего manifest для `css/app.css` | CI / статика Django | Перед pytest добавлен `python manage.py collectstatic --noinput`; следующий CI показал зелёные `quality` и `docker` | Исправлено, подтверждено CI |
| OF-003 | Падение производительности при 125–200 RPS с одним Gunicorn worker, высокий p95 и `dropped_iterations` | Производительность | Увеличено число workers с 1 до 4 (по 4 threads); на 200 RPS получены p95 13,19 мс, 0 HTTP-ошибок и 0 пропущенных итераций | Исправлено для проверенного сценария |

## Новые дефекты при пользовательской проверке

Не зарегистрированы по сообщённым результатам восьми сценариев. Это не доказывает отсутствия иных дефектов.

## Ограничения и открытые задачи (не считать дефектами без дополнительной проверки)

| ID | Описание | Следующее действие | Статус |
|---|---|---|---|
| OF-R01 | Docker-пакет `ghcr.io/ramig2007/officeflow:latest` приватный | Предоставить преподавателю доступ или подготовить разрешённый способ доставки | Открытая организационная задача |
| OF-R02 | Alertmanager маршрутизирует в `null-receiver`, сообщения не доставляются внешним адресатам | Настроить реальный receiver, если это требуется ТЗ/демонстрацией | Открытая настройка |
| OF-R03 | Длительный SLA 99,9 %, нагрузка записи и большое число одновременных пользователей не подтверждены текущим тестом | При необходимости выполнить отдельные испытания | Не проверено |

## Правила ведения реестра

Для новых дефектов фиксировать дату, шаги воспроизведения, ожидаемый и фактический результат, серьёзность, ответственного, способ исправления и ссылку на подтверждение повторной проверки.
