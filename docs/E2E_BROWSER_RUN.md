# OfficeFlow — браузерное тестирование Playwright

## Текущая версия: 27/27 в PR CI #117 (21.11.2026)

**Важно:** `e2e/browser_smoke.py` сейчас выполняет `27` сквозных браузерных проверок, включая **изменяющие данные операции**. Он создаёт пользователей, бронирования и переговорные, изменяет и отменяет их, назначает и отзывает административную роль. **Не запускайте этот сценарий против рабочей базы или обычного локального сайта с нужными данными.**

Подтверждённый результат: [CI #117](https://github.com/Ramig2007/OfficeFlow/actions/runs/44829732693) — `quality` и `docker` **Success**, строка журнала `RESULT: 27/27 browser acceptance checks passed`. Все действия выполнялись на одноразовом CI Compose-стенде; после испытаний временные volumes удалялись.

Автоматически проверяются:

1. Анонимный доступ, вход сотрудника, главная страница;
2. Каталог, карточка переговорной, VIP-фильтр, расписание, история;
3. Запрет обычному пользователю доступа к административным маршрутам;
4. Отображение без горизонтального переполнения на 375 и 768 px, desktop 1440 px;
5. Создание, редактирование и отмена обычного бронирования;
6. VIP-заявки, решение администратора, причина отказа и видимость статуса;
7. Создание, редактирование и деактивация переговорной;
8. Фильтрация отчёта по дате и комнате с CSV-экспортом;
9. Самостоятельная регистрация сотрудника и проверка базовых прав;
10. Назначение и отзыв административной роли с проверкой фактического доступа;
11. Выход из аккаунта и обязательная повторная авторизация.

Каждый из этих пунктов может включать несколько внутренних проверок; **официальный счёт итогового теста — 27 сценариев**. Скриншоты загружаются в GitHub Actions artifact `officeflow-browser-e2e` с хранением 7 дней. При падении сценария формируется `failure.png`.

## Безопасный повтор

Рекомендуемый вариант — запустить `OfficeFlow CI` из GitHub Actions на временном PR/ветке. Его Docker job автоматически:

- поднимает совершенно новый Compose stack и отдельную PostgreSQL;
- создаёт только синтетические `DEBUG=1` demo fixtures;
- собирает Chromium test image и выполняет `e2e/browser_smoke.py`;
- загружает скриншоты как artifact;
- уничтожает контейнеры и тестовые volumes после выполнения.

**Не используйте прежнюю команду `docker run officeflow-e2e` против обычного уже заполненного локального Docker-стенда.** Если требуется локальный прогон, сначала разверните полностью отдельную тестовую среду с другой базой и отдельными volumes. Никогда не удаляйте рабочие Docker volumes только ради повторения этих тестов.

## Ограничения

Автоматические тесты доказывают правильность перечисленных сценариев только на проверенном временном окружении. Они не подтверждают промышленный SLA, доступность публичного HTTPS, независимую ручную приёмку или отсутствие любых уязвимостей. Нагрузочные испытания 1000 синтетических пользователей и операций записи отдельно документированы в `docs/SCALE_RESULTS_2026-11-21.md`.
